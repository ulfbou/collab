# Boundary Attempt contract

`collab/boundary-attempt/v1` is a pure, immutable, in-memory record of one attempt against exactly one existing Boundary. Normalization version is `1`.

`create_boundary_attempt` accepts a Boundary mapping, its authoritative ordered operation plan, a closed caller-supplied `operationPlanAuthority` assertion, one record per planned operation, immutable Receipt mappings, and a closed applicability context containing candidate, configuration, and validator identities. `operationPlanAuthority` contains exactly `completenessEstablished: true` and `scopeConformityEstablished: true`; missing, false, non-boolean, or additional members fail closed. The assertion records prior establishment under the existing Boundary authority. It does not create, expand, reinterpret, or replace that authority, derive authority from free text, or execute or validate external operations. It rejects missing or malformed boundaries, extra or reordered operations, ordinal gaps or duplicates, duplicate operation IDs or receipt associations, contradictory status sequences, multiple failures, unknown properties, and inferred ownership.

Each operation is `COMPLETED`, `FAILED`, or `NOT_ATTEMPTED`. A failed operation has a machine-readable code, explicit owner (`CANDIDATE`, `WORKFLOW`, `ENVIRONMENT`, `AUTHORITY`, or `CONSISTENCY`), matching operation ID, and optional non-authoritative message. Completed records before a later failure remain unchanged.

Receipt objects are never rewritten. Each receipt identity is associated with one operation. Applicability is evaluated exclusively by `collab.boundary_contracts.evaluate_receipt_applicability()` using the attempt-level context. Workflow, environment, authority, and consistency failures do not themselves invalidate still-applicable receipts. A changed candidate identity makes only receipts bound to the old candidate inapplicable; unrelated applicability remains governed by the authoritative evaluator.

`resumeOperationId` is the failed operation, otherwise the first not-attempted operation, otherwise null. Authority and consistency failures keep that smallest incomplete operation visible but set `automaticContinuationAllowed` to false. The value describes state only. It performs no operation, retry, repair, publication, acceptance, integration, synchronization, cleanup, I/O, or durable transition and does not replace `collab/continuation-decision/v1`.

`operationPlanIdentity` is `sha256:operation-plan:v1:` plus SHA-256 over canonical JSON for the complete normalized ordered `operationPlan`. It is derived by the constructor and changes when material plan content or ordering changes. `attemptId` is `sha256:boundary-attempt:v1:` plus SHA-256 over canonical JSON for the complete normalized attempt except the ID itself, including `operationPlanIdentity` and the closed `operationPlanAuthority` assertion. Meaningful plan order is semantic and affects identity. Observable mappings and sequences are recursively immutable; canonical serialization is provided by `serialize_boundary_attempt`.
